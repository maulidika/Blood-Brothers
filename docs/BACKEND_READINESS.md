# Backend readiness plan (NOT implemented yet - design only)

Vision: after the offline build is stable, run an independent server and reuse this codebase online.
Nothing below changes offline behaviour.

## 1. Seams already in place
| Seam | Today | Online later |
|---|---|---|
| `SaveStore` (`scripts/services/save_store.gd`) | local JSON, atomic + backup | `RemoteSaveStore`: same `load_state/save_state`, HTTP + token; keep local as cache |
| `Game` commands (`begin_stage`, `finish_stage`, `pact_roll`, `combine`, `evolve`, `equip`, `enhance`, `sell`, `set_brigade_slot`) | mutate local state | become API calls; server validates and returns the same result dictionaries |
| `BattleEngine` (pure, seeded) | client simulates | server simulates with the seed, returns events (client only replays) |
| `Data` | local JSON | `GET /masterdata/<version>` cached locally |
| uid strings | generated by `Game.add_fam/add_gear` | server-issued ids |

## 2. Refactors to do when starting online (kept out of milestone 1 on purpose)
- Extract `Game` into `PlayerRepository` (state) + `GameService` (commands). Commands already return plain
  dictionaries, so this is a mechanical split.
- Move randomness (`rng`) behind a `RandomSource` so the server owns drops/pact rolls.
- Replace `Time.get_unix_time_from_system()` energy regen with server time.
- Add `schema_version` migrations in `SaveStore`.

## 3. Proposed backend (independent server, own protocol; no Mobage/DeNA services, no auth bypass)
- Auth: own accounts (email/OAuth/device token) -> short-lived JWT + refresh.
- REST/JSON (WebSocket later for realtime PvP/raid):
  `POST /auth/*`, `GET/PUT /profile`, `GET /save` + `PUT /save` (versioned, conflict via `if_version`),
  `POST /battle/stage/{id}/start|finish`, `POST /pact/{tier}`, `POST /familiar/combine|evolve|sell`,
  `POST /gear/enhance|equip`, `GET /masterdata/{version}`, `GET /ranking`.
- Storage: Postgres (`players`, `familiars`, `gear`, `brigades`, `progress`, `transactions`), Redis for sessions/queues.
- Multiplayer: async arena first (store parties, simulate with `BattleEngine` + seed), then raid boss
  (shared HP pool, matches the original Raid/World Boss structure seen in the client).
- Anti-cheat: server-authoritative rewards, signed battle seeds, rate limits, audit table.
- Content: server-side master data lets live events be added like the original (`Event*Cache` classes).

## 4. Decision log
- Do not couple screens to storage or to the network (rule 1).
- Do not trade fidelity for online features; online-only needs sit behind the seams above.
