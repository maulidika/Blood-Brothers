# Architecture (offline milestone 1)

```
scenes/main.tscn  ->  scripts/main.gd        router, header, dialogs
                          |
        scripts/screens/*.gd                 PRESENTATION only (build UI, call Game, render results)
                          |
        scripts/game.gd   (autoload Game)    APPLICATION: player state, economy, progression, rewards
           |        |
           |        +--> scripts/services/save_store.gd   STORAGE seam (local JSON today)
           |
           +--> scripts/battle_engine.gd     DOMAIN: deterministic battle sim (seeded RNG, pure data in/out)
           +--> scripts/data.gd (Data)       STATIC DATA: data/*.json (familiars, skills, zones, gear, pact)
scripts/assets.gd (Assets)  sprites/audio lookup (original assets in assets/original/)
scripts/ui.gd     (UI)      sprite-based widgets
```

## Rules that keep the codebase online-ready
1. **Screens never touch state directly.** They call `Game.<command>()` and render the returned dictionary.
2. **`BattleEngine` is pure**: input = unit dictionaries + seed, output = `events[]` + `result`. It reads
   `Data` only. A server can run the identical code (Godot headless) or a port, and replay from `seed`.
3. **State is one JSON-serialisable dictionary** (`Game.s`, schema `version`). Ids are opaque strings (`uid`).
4. **Storage is behind `SaveStore`** (`load_state` / `save_state`).
5. **Static data is JSON** generated by `tools/gen_data.py`; swapping it for server-provided master data
   (as in the 2015 game, where `Cache`/`Entity` classes were filled from the server) only changes `Data._ready`.
6. **Original UI/audio live only in `assets/original/`** and are addressed by sprite name (`Assets.tex(path)`).

## Fidelity notes (what is evidence vs. reconstruction)
Evidence from the APK client JS: 4 stats ATK/DEF/WIS/AGI + HP; three formation lines (Front/Center/Rear);
target ranges (front/rear/center/all/random N); skill families (attack, magic, heal, buff/debuff, drain,
counter, protect, taunt, revive, steal...); battle types (normal, raid boss, PvP, arena, boss gacha);
raid boss uses a 2-line layout; 4 resistances/shields; 1x/1.5x/2x battle speed; 11 races; 6 rarities.
Reconstruction (assumptions): all numeric formulas, the master data (names, stats, quests, rates), energy/rank curves.
The real numbers were server-side and are NOT in the APKs.
